
# 정리
test3부터 나타나는 `lst.append`, `lst = [...]`는 그 alias(reference)를 직접 조작하느냐, 혹은 alias를 교체하느냐의 차이이다.\
가변 객체의 대입연산은 reference의 교체로 이루어지고, 함수의 scope상 원래 지역변수 lst에 새로운 객체인 `[0, 0, 0]`이 할당 되었다.\
이는 전역 변수 data에 영형을 주지 않았다. \
반면 append의 경우 직접적으로 전역변수 data의 referernce를 가져왔기 때문에 그 내부의 정보를 조작해도 밖에서는 보이는 것이다.

test5의 경우는 default값이 가변 객체라서 생긴 것일 가능성이 크다. \
만약 아니었다면, 보통 이는 값의 교체로 이어질 것이고 그럼 default값이 호출 후에도 다시 쓰이는 일은 일어나지 않았을 것 같다. \
실제로 그런진 테스트 해봐야할 것 같지만, 그렇기 때문에 사실 `bucket=None`과 같은 null값 확인 패턴이 생긴 것이다. \
이후에 `None`이 맞으면 `bucket=[]`으로 대입하는 형식으로 이루어지는 것이 깔끔하다.
